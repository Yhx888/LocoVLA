# 教程写作与验收规范

## 1. 中心原则

课程面向只学过高中数学、没有机器人背景的学习者，但最终证据门槛对齐具身智能运动控制岗位。降低理解门槛不等于降低工程标准。

每个内容模块必须回答：这是什么、为什么需要、怎样计算或使用、何时失效。任何章节在代码、测试和可视化没有完成前只能标记“规划中”。

## 2. 每章固定结构

1. 岗位任务：给出真实交付物和风险。
2. 学习目标：理解、推导、实现三个层级。
3. 前置关卡：允许诊断后跳过，不能隐藏依赖。
4. 错误基线：先观察视频、曲线或日志，再读结论。
5. 直觉与概念：生活类比必须映射回 Upkie。
6. 教科书展开：假设、符号、单位、动机、推导、算例、代码。
7. 动手检查点：完整命令、预期输出、失败诊断。
8. 三重证据：视觉、日志、自动测试。
9. 故障挑战：注入错误并定位第一处异常。
10. 三档任务：基础、岗位挑战、开放探索。
11. 复盘与面试：结论必须能在本章找到依据。
12. 下一关：说明本关产物怎样成为后续输入。

## 3. 八类内容

### 3.1 公式推导

按七层递进：直觉 -> 符号拆解 -> 物理意义 -> 设计动机 -> 不跳步推导 -> 数值算例 -> Upkie 代码映射。

每个公式必须写明：

- 假设与平衡点；
- 每个符号的含义和 SI 单位；
- 离散时间时的采样周期；
- 适用范围与失效条件；
- 至少一个能手算复核的数值例子；
- 配置字段、数组顺序和代码行之间的对应。

禁止“由此可得”跳过关键代数，也禁止把经验增益称为 Riccati 解。

### 3.2 概念定义

按四步写：一句大白话 -> 拆解术语/字母 -> Upkie 具体实例 -> 为什么对岗位有用。概念存在层级、循环或数据流时必须配图。

### 3.3 架构描述

必须包含模块、职责、数据流、接口边界、这样划分的原因，并配 SVG 或 Mermaid。图中标注数据形状、单位、频率和安全边界，不能只画漂亮方框。

### 3.4 代码分析

先给整体流程，再展示不超过 30 行的核心代码，最后解释 1-3 行关键设计原因。说明输入、输出、状态、副作用和异常路径；不要整文件粘贴后逐行复述。

### 3.5 操作验证

每项操作给完整命令、典型输出和至少两种常见失败。验证必须同时覆盖：

- 视觉：应看到什么现象；
- 日志：哪些数值应在什么范围；
- 测试：哪条命令自动判定。

预期结果来自真实运行记录；未运行的命令必须标记“待验收”。

### 3.6 对比分析

先分别一句话定义，再用至少五个维度比较理论基础、输入、输出、假设、约束、计算量和场景。最后给选择条件与边界，不能写成“高级方法一定更好”。

### 3.7 参数调优

每个参数写效果、范围、过大/过小现象和调参顺序。一次只改变一个假设；保存配置 diff、固定 seed 和前后曲线。若三次调参仍失败，应重新检查模型、平衡点和架构。

### 3.8 问答检测

基础概念约 60%，应用诊断约 30%，开放权衡约 10%。答案采用“结论 + 关键原因 + 必要边界”，且正文必须提供证据。

## 4. 可视化路由

- 时序、状态机、思维导图、类图、甘特图：Mermaid。
- 控制框图、能力分层、物理结构、流程与对比：SVG 画板。
- 实验数据：Plotly/Matplotlib，并保存原始数值。
- 仿真行为：MP4，同时保留对应日志和 seed。

飞书 SVG 必须按项目 `AGENTS.md` 的白名单渲染、检查并导出，达到 0 errors / 0 warnings 后才可同步。

## 5. 正向激励

正向激励来自专业进步证据，不使用儿童化积分。每次通过展示：基线与改进对比、关键指标变化、获得的岗位能力、作品集路径和下一步入口。失败页面展示证据链和诊断路线，不只显示红色错误。

# 47 答辩材料

> 关卡：47（oral_defense 外部人工答辩准备；本地自动流程不能判定通过）
> 文档目的：把整个课程已建成的控制、估计、RL、VLA、工程部署、安全、文档体系整理成可口头答辩的论证链。

## 1. 设计动机

### 1.1 为什么选 PD 控制作为入门基线
- 简单可解释：高中数学就能理解 `u = Kp*e + Kd*ė`，没有积分与状态空间抽象，新手第一关就能动手调参。
- 充分性：双轮倒立摆在小角度附近线性化后，PD 反馈可对位置、速度、俯仰、俯仰角速度分别施加增益，构造等效的"弹簧—阻尼"系统，使闭环极点落在左半平面。
- 局限性：大角度时 `sin(θ)≈θ` 失效，PD 在非线性区会发散；无积分项导致对持续扰动的稳态误差不可消除；多变量耦合在四状态模型中无法显式解耦。
- 课程位置：第 12 关（`test_wheel_balancer_keeps_floating_robot_upright_for_five_seconds`），通过 5 秒直立测试作为入门验收门槛。

### 1.2 为什么引入 LQR
- 最优控制视角：通过代价函数 `J = ∫(xᵀQx + uᵀRu)dt` 权衡状态偏差与控制能耗，自动求解最优反馈增益 `K = R⁻¹BᵀP`，无需手工逐通道调参。
- 多输入多输出：四状态线性模型 `[x, ẋ, θ, θ̇]` 与两路控制输入（左右轮端力矩）耦合，LQR 用一个 Riccati 方程同时优化所有通道，避免 PD 的逐通道盲调。
- 可控性：通过可控性矩阵 `[B, AB, A²B, ...]` 秩等于状态维度验证系统可驱动，确保 LQR 解存在。
- 课程位置：第 17 关，要求闭环极点全部位于左半平面且阻尼比 `ζ≥0.7`。

### 1.3 为什么引入 RL
- 非线性、随机化、训练分布外泛化：PD 与 LQR 依赖线性化模型，在域随机化（摩擦、质量、电机延迟）下会失稳；RL 通过策略梯度直接在随机化分布上优化期望回报，天然处理非线性。
- 残差 RL：经典控制器做基线保证安全底线，RL 只学习残差 `π(s) = u_base + Δu(s)`，缩小探索空间、提升样本效率、降低训练期失控风险。
- PPO 算法选择理由：on-policy 无需重放缓冲区、训练稳定、超参鲁棒、样本效率可接受（课程在 1000-10000 步内可收敛），适合教学场景。
- 课程位置：第 27-31 关，要求 bootstrap 95% 置信区间非退化（不含 0），证明策略显著优于基线。

### 1.4 为什么引入 VLA
- 高层语义指令（"去红色目标"）→ 底层动作：经典控制与 RL 只能接收低层指令（速度、位置），无法直接处理自然语言或视觉语义；VLA 把感知、语言、动作统一在一个策略中。
- 行为克隆作为入门：监督学习可解释、训练稳定、不涉及 RL 的方差问题；课程先建立"专家轨迹 → 模仿策略"的基线，再讨论 DAgger、扩散策略等改进。
- 课程位置：第 32-37 关，要求 VLA 评估报告含 `collision_rate`、`safety_state_transition_count`、`recovery_success_rate` 三项安全指标。

### 1.5 为什么引入 C++/ROS2
- 实时性：Python GIL 无法保证 100Hz 控制循环的抖动 `≤10.5ms`，C++ 实现配合 `timeBeginPeriod(1)` 可把平均周期压到 10ms 附近。
- 工业部署：ROS2 是机器人中间件事实标准，DDS 后端支持跨网段、QoS 策略、节点发现，是实机部署的必经路径。
- 数值一致性：C++ 和 Python 双实现验证 parity，固定 seed 生成 1000 组输入，逐项比较输出，容差 `1e-9`，保证算法迁移不引入数值漂移。
- 课程位置：第 38-43 关，含 CMake 依赖图审计、ROS2 QoS 验证、日志契约测试、安全状态机测试。

## 3. 局限性

### 3.1 Windows 非硬实时
- Windows 默认定时器分辨率 15.6ms，1ms 分辨率需 `timeBeginPeriod(1)`，且仅降低平均抖动，不提供硬实时保证。
- 100Hz 控制循环在 WSL2 中可实现，但内核调度仍可能被高优先级中断打断，单次抖动可能超过 15ms。
- 实机部署需要 RT Linux（PREEMPT_RT）、Xenomai 或专用运动控制卡，配合优先级继承协议避免优先级反转。

### 3.2 仿真与实机差距
- 接触模型：MuJoCo soft contact 用 spring-damper 近似，实机轮地接触是刚性冲击，瞬时力矩峰值差异显著。
- 摩擦：库仑摩擦模型简化，未建模静摩擦、Stribeck 效应、各向异性；低速爬行时偏差最大。
- 传感器噪声：仿真噪声为高斯白噪声，实机 IMU 含温度漂移、随机游走、量化噪声；编码器含量化与电气噪声。
- Sim2Real gap：domain randomization 部分缓解（在摩擦、质量、惯量、电机延迟上随机化），但不能完全覆盖未建模动态。

### 3.3 单目视觉感知
- 深度缺失：单目相机无法直接获取深度，依赖运动恢复结构或学习型深度估计，误差大。
- 颜色检测：HSV 阈值对光照敏感，同一目标在日光、白炽灯、LED 下 V 通道差异显著，需自适应阈值或迁移到深度学习检测。
- VLA 模型：行为克隆泛化能力有限，分布外场景（未见过的颜色、遮挡、运动模式）会失效；复合误差使小错误在长时程任务中累积放大。

## 4. 改进方向

### 4.1 Sim2Real
- 域随机化扩展：在摩擦系数、质量、惯量、电机延迟、传感器偏置上联合随机化，提升策略鲁棒性。
- 系统辨识：用实机数据反推仿真参数（最小二乘或贝叶斯辨识），缩小基线模型偏差。
- 域适配：GAN 或对抗训练学习 sim→real 的残差策略，让策略在仿真中学习如何补偿实机偏差。

### 4.2 VLA 闭环
- 当前 VLA 是开环行为克隆，无环境反馈，误差不可纠正。
- 改进路径一：RL fine-tuning，在行为克隆初始化后用 PPO 微调，引入奖励信号修正分布外行为。
- 改进路径二：DAgger，在线收集策略失误样本并由专家标注，迭代缩小分布偏差。
- 改进路径三：扩散策略，建模动作分布而非点估计，提升多模态任务的表达能力。

### 4.3 硬件迁移
- 当前所有关卡（除 H01）都在仿真，H02-H10 需要真实硬件。
- 改进：实机数据采集管道（含时间对齐、标定、异常剔除）；安全监督器在实机上强制速度/力矩上限；人工接管机制（急停按钮 + 一键回退到经典控制）。

### 4.4 实时性升级
- RT Linux（PREEMPT_RT 补丁）或 Xenomai 提供微秒级调度抖动。
- 优先级继承协议避免优先级反转，控制线程设为 SCHED_FIFO 最高优先级。
- DMA 通信减少 CPU 中断负载，传感器数据直接写入环形缓冲区，控制线程只读取无锁队列。

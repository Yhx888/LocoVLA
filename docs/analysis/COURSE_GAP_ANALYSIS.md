## 二、课程缺口（按严重程度排序）

### 🔴 缺口 1：控制理论深度不够

**现状：** 课程只覆盖了 PD 和 LQR，属于控制理论的入门部分。

**缺失内容：**

| 缺失知识点 | 为什么重要 | 大厂面试频率 |
|------------|-----------|-------------|
| MPC（Model Predictive Control） | 腿足/轮足机器人控制的核心算法，处理约束的能力远超 LQR | ⭐⭐⭐⭐⭐ 几乎必考 |
| 状态估计（EKF/UKF） | 真实机器人必须融合 IMU + 编码器 + 力矩传感器来估计状态 | ⭐⭐⭐⭐ 高频 |
| 动力学建模推导 | 拉格朗日法/牛顿-欧拉法推导多连杆机构动力学 | ⭐⭐⭐⭐ 高频 |
| 轨迹优化 | 直接配点法、打靶法，用于生成行走/蹲起轨迹 | ⭐⭐⭐ 中频 |
| 最优控制理论 | 变分法、HJB 方程、Pontryagin 极大值原理 | ⭐⭐⭐ 中频 |
| 凸优化 / QP 求解 | MPC 最终要转化为 QP 问题求解 | ⭐⭐⭐ 中频 |

**面试典型题（课程无法回答）：**
- "推导一下五连杆机构的动力学方程"
- "MPC 的 QP 怎么列？约束怎么加？"
- "EKF 和 UKF 的区别？什么时候用哪个？"
- "LQR 和 MPC 的本质区别是什么？"

---

### 🔴 缺口 2：真实硬件经验为零

**现状：** 课程明确定位"不接真实硬件"，所有内容都在仿真中完成。

**缺失内容：**

| 缺失知识点 | 为什么重要 |
|------------|-----------|
| 电机驱动与通信 | CAN / EtherCAT 协议，电机力矩控制模式 |
| 传感器融合 | IMU 数据处理、编码器读数、力矩传感器标定 |
| 实时系统 | RT-Linux / RTOS，控制回路的实时性保证 |
| 参数辨识 | 摩擦力、电机常数、连杆惯量的实际测量 |
| 调试能力 | 示波器看电流环、日志分析、故障排查 |
| 安全意识 | 急停设计、力矩限位、跌倒保护 |

> **这是最大短板。** 大厂控制岗几乎都要求"有实际调试经验"，纯仿真在简历筛选阶段就会被扣分。面试官会问"你实际调过机器人吗？遇到过什么问题？"——纯仿真的回答会显得很单薄。

---

### 🔴 缺口 3：C++ 工程能力不足

**现状：** 课程全部使用 Python，而大厂控制算法基本都是 C++ 跑在嵌入式上。

**缺失内容：**

| 缺失知识点 | 为什么重要 |
|------------|-----------|
| C++ 控制算法实现 | 嵌入式平台只支持 C/C++，Python 无法部署 |
| Eigen 线性代数库 | 控制算法中的矩阵运算标准工具 |
| CMake 构建系统 | C++ 项目的工程化管理 |
| ROS/ROS2 | 机器人系统的通信中间件，大厂标配 |
| 多线程 / 实时调度 | 控制回路、感知、规划需要并行运行 |
| 内存管理 | 嵌入式资源受限，不能用 Python 的 GC |

---

### 🟡 缺口 4：数学基础未验证

**现状：** 课程中"用"了线性代数和优化，但没有推导过程。

**缺失内容：**

| 缺失知识点 | 课程现状 | 大厂要求 |
|------------|---------|---------|
| 线性代数 | 直接调 NumPy | 能手推 SVD、特征值分解、矩阵求导 |
| 最优控制 | 直接用 LQR 公式 | 能从变分法推导 LQR 的 Riccati 方程 |
| 优化理论 | 直接调求解器 | 能解释 QP/KKT 条件/对偶问题 |
| 概率与随机过程 | 域随机化直接采样 | 能解释马尔可夫决策过程、贝叶斯估计 |

---

### 🟡 缺口 5：算法面试能力

**现状：** 课程不涉及算法刷题。

**大厂面试要求：**
- LeetCode 中等难度（数组、链表、树、动态规划、二分查找）
- 手撕代码能力（C++ 或 Python，30 分钟内完成）
- 时间/空间复杂度分析

## 三、补充路线图

### 第一阶段：课程内可补充的内容（2-3 个月）

这些内容可以直接加入课程体系，不需要额外硬件。

#### 3.1 新增 Lesson：MPC 控制（建议插入 Lesson 3.5）

```
目标：用 MPC 实现 Upkie 平衡控制
内容：
  - MPC 问题建模（状态空间、代价函数、约束）
  - 用 casadi 或 osqp 求解 QP
  - 与 LQR 对比（处理约束的能力差异）
  - 参数调优（预测时域、控制时域、权重矩阵）
产出：一个能在 MuJoCo 中运行的 MPC 平衡控制器
预计时间：2-3 周
```

#### 3.2 新增 Lesson：状态估计（建议插入 Lesson 4.5）

```
目标：用 EKF 融合 IMU + 关节编码器估计躯干姿态
内容：
  - 状态估计问题定义（为什么不能直接用传感器读数）
  - EKF 推导（预测步 + 更新步）
  - 在 Upkie 上实现：融合 IMU 和编码器
  - 与"直接使用真值"对比，理解估计误差
产出：一个 EKF 状态估计器
预计时间：1-2 周
```

#### 3.3 新增 Lesson：动力学建模（建议插入 Lesson 2.5）

```
目标：推导 Upkie 简化模型的动力学方程
内容：
  - 拉格朗日力学基础
  - 轮式倒立摆动力学推导（手推，不依赖库）
  - 用 Pinocchio 验证手推结果
  - 五连杆机构动力学（选做）
产出：一份手写推导笔记 + Pinocchio 验证代码
预计时间：1-2 周
```

#### 3.4 新增 Lesson：C++ 控制回路 mini-project

```
目标：用 C++ 实现一个最小控制回路，证明不是只会 Python
内容：
  - CMake 项目结构
  - Eigen 矩阵运算
  - 实现 PD 控制器（C++ 版本）
  - 通过 socket/文件与 MuJoCo Python 仿真通信
产出：一个 C++ PD 控制器 + 构建脚本
预计时间：2-3 周
```

#### 3.5 每节增加面试题（建议 2-3 道/节）

| 课程 | 示例面试题 |
|------|-----------|
| Lesson 03 (PD) | "PD 控制中 D 项的作用？过大/过小会怎样？" |
| Lesson 04 (LQR) | "为什么 LQR 用二次代价函数？Q 和 R 的物理意义？" |
| Lesson 05 (RL) | "PPO 的 clip 机制解决了什么问题？" |
| Lesson 06 (Reward) | "reward shaping 可能引入什么问题？如何设计 sparse reward？" |
| Lesson 07 (Sim2Real) | "domain randomization 的理论依据是什么？" |

### 第二阶段：课程外需要补充的内容（3-6 个月）

这些内容超出课程范围，但入职必须具备。

#### 3.6 真实硬件项目（最重要）

**推荐硬件选择：**

| 方案 | 预算 | 适合方向 | 推荐产品 |
|------|------|---------|---------|
| 平衡小车 | ¥200-500 | 入门，验证 PID/LQR/MPC | STM32 平衡小车套件 |
| 四足机器人 | ¥2000-5000 | 腿足控制，简历加分 | 宇树 Go1 Edu / DJI RoboMaster |
| 轮腿机器人 | ¥3000-8000 | 与课程最相关 | 自制轮腿 / Upkie 实物（如有渠道） |

**必须完成的里程碑：**
1. 搭建硬件环境（电机驱动、传感器读取、通信链路）
2. 跑通一个基础控制 demo（平衡/站立）
3. 实现状态估计（IMU + 编码器融合）
4. 调参并记录过程（这是面试的重要素材）
5. 遇到并解决至少 3 个真实问题（如电机抖动、通信延迟、传感器噪声）

#### 3.7 ROS2 集成

```
目标：把课程控制器封装成 ROS2 node
内容：
  - ROS2 基础（topic、service、action）
  - 把 PD/MPC 控制器封装为 node
  - 用 Gazebo 或 MuJoCo 做 sim-to-sim demo
  - launch 文件、参数配置
预计时间：2-3 周
```

#### 3.8 论文精读（至少 3 篇）

| 论文 | 为什么读 | 读完能聊什么 |
|------|---------|-------------|
| Upkie 原始论文 | 了解课程所用机器人的设计思路 | 开源硬件设计、控制架构 |
| MIT Mini Cheetah 控制论文 | 腿足控制的经典工作 | MPC + WBC 架构 |
| Residual RL 相关论文 | 课程 Lesson 07 的理论基础 | 混合控制的优劣 |
| 任意一篇 recent survey | 了解领域全貌 | "你对这个方向怎么看？" |

#### 3.9 算法刷题

```
目标：LeetCode 中等难度 100+ 题
重点：数组、链表、树、图、动态规划、二分查找
语言：C++（同时练工程能力）
工具：LeetCode / 牛客网
预计时间：每天 1-2 题，持续 3-4 个月
```

## 六、总结

**一句话：** 这套课程能让你理解控制工程师在做什么，但要成为控制工程师，还需要在 **理论深度**、**C++ 工程**、**真实硬件** 三个方向各补 30-50% 的内容。

**课程本身最大的优化机会：** 加上 MPC 和状态估计两节，求职价值会提升一个档次——这两项是大厂控制岗的"入场券"。

**不要忽略的软实力：**
- 能讲清楚"我做了什么、为什么这么做、遇到了什么问题、怎么解决的"
- 能在白板上推导基本公式（LQR、MPC、EKF）
- 能用 C++ 手写一个简单控制器
- 能讨论"这个方向未来会怎么发展"

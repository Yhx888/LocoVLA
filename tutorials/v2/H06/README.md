## 复盘与面试

1. 本关最关键的假设是什么？失效时第一个可观测信号是什么？

<!-- upkie-qa:H06-q1 -->
最关键的假设是：互补滤波公式 `theta_k = alpha*(theta_{k-1} + omega*dt) + (1-alpha)*theta_acc` 中，陀螺仪角速度 omega 在短期内无偏，加速度计角度 theta_acc 在长期内无偏，两者的误差特性互补。这个假设的物理依据是：陀螺仪积分漂移是低频误差（随时间累积），加速度计噪声是高频误差（振动、冲击引起的瞬时偏差）；alpha 接近 1 时信任陀螺仪（短期精确），alpha 接近 0 时信任加速度计（长期校正）。假设失效时，第一个可观测信号取决于哪个传感器出了问题：如果陀螺仪偏置过大（比如温度变化导致零点漂移），theta_k 会出现缓慢的单向漂移，即使机器人静止不动，估计角度也会持续偏离真实值；如果加速度计受到持续振动（电机运行时的机械振动），theta_acc 会有高频噪声，theta_k 会出现与振动同频的纹波。本关正文的"先低能量验证，再逐级闭环"在这里的体现是：先在静止状态下验证 theta_k 的漂移速率（应该 <0.1°/min），再在电机运行状态下验证振动对 theta_acc 的影响，最后才把姿态估计接入平衡控制环。需要注意的是，本关当前建设状态为"规划中"，`course_checkpoint.py --chapter H06` 会明确拒绝验收。面试时的判断框架：姿态估计问题的排查顺序是"静止漂移 → 振动噪声 → alpha 参数 → 传感器硬件"，从最容易验证的开始。常见误区是"漂移大就减小 alpha（更信任加速度计）"——这会同时引入更多振动噪声，正确的做法是先校准陀螺仪偏置，再调 alpha。
<!-- /upkie-qa -->

2. 为什么当前接口、单位和限幅这样设计？有哪些可替代方案？

<!-- upkie-qa:H06-q2 -->
`theta_k = alpha*(theta_{k-1} + omega*dt) + (1-alpha)*theta_acc` 里所有角度用 rad，角速度用 rad/s，dt 用 s，与课程软件部分的状态向量（第 38 章的 `[m, m/s, rad, rad/s]`）保持单位一致。alpha 是无量纲的融合权重，取值范围 (0, 1)，典型值 0.98~0.99（对应时间常数约 0.5~1 s）：alpha=0.98 意味着加速度计的校正时间常数约 50 个采样周期，足以滤除电机振动引起的高频噪声，同时能在几秒内校正陀螺仪漂移。theta_acc 的计算 `atan2(acc_y, acc_z)` 假设机器人只绕 y 轴（俯仰轴）转动，且加速度计只受重力——这个假设在机器人加速运动时失效（线性加速度会叠加到重力上，theta_acc 出现偏差），这是互补滤波的固有局限。限幅设计：theta_k 应该被限制在物理合理范围内（比如 ±π/2，超过这个角度机器人已经翻倒，姿态估计没有意义），超出范围的估计值应该触发故障标志而不是继续参与控制。替代方案：扩展卡尔曼滤波（EKF，第 19~24 章的状态估计内容），能同时估计角度和陀螺仪偏置，精度更高但计算量更大、调参更复杂；或者用 Madgwick/Mahony 算法（专为 IMU 设计的非线性互补滤波），在四元数空间工作，避免万向锁，但实现复杂度更高。需要注意的是，本关当前为规划中状态，具体的 alpha 值和采样率尚未确定。面试时的判断框架：互补滤波 vs EKF 的选择依据是"计算资源够不够"和"精度要求高不高"——对于 100 Hz 的平衡控制，互补滤波的精度通常足够，EKF 的优势在更高精度的导航场景。常见误区是"alpha 越大越好"——alpha=1 等于完全不用加速度计，陀螺仪漂移无法校正，几分钟内角度估计就会完全偏离。
<!-- /upkie-qa -->

3. 你能用哪三份证据证明结果可复现？

<!-- upkie-qa:H06-q3 -->
姿态估计的可复现性证据需要覆盖"静态精度、动态精度、鲁棒性"三个层次。第一份是静态漂移记录：机器人静止放置，记录 theta_k 在 5 分钟内的变化，计算漂移速率（°/min）；这是陀螺仪偏置和 alpha 参数是否合理的直接证据，让别人能在同一台机器上重测得到相近的漂移速率（环境温度相同的情况下）。第二份是动态精度记录：用已知角度的夹具（比如精密转台）将机器人倾斜到多个已知角度（比如 ±5°、±10°、±20°），比较 theta_k 的稳态读数与真实角度的偏差；这是加速度计校正是否有效的证据，验证 `(1-alpha)*theta_acc` 这一项在长期内确实把 theta_k 拉回了真实值。第三份是振动鲁棒性记录：电机运行状态下（不同转速），记录 theta_k 的纹波幅度（峰峰值），与电机静止时对比；这是"先低能量验证，再逐级闭环"原则的体现，验证电机振动没有通过加速度计通道污染姿态估计。三份证据的分工：静态记录回答"漂移有多大"，动态记录回答"稳态精度够不够"，振动记录回答"实际运行环境下还能不能用"。需要注意的是，本关当前为规划中状态，这三份证据的具体格式和验收标准尚未建立。面试时的判断框架：姿态估计证据的可复现性依赖固定的环境条件——温度影响陀螺仪偏置，振动影响加速度计噪声，不记录这些条件的测量数据没有可比性。常见误区是"只测静止精度"——静止时精度好不代表运行时精度好，电机振动是实际部署中最大的姿态估计干扰源。
<!-- /upkie-qa -->

4. 如果指标退化 20%，你先查模型、数据、控制还是部署？为什么？

<!-- upkie-qa:H06-q4 -->
先查部署，在 IMU 语境下对应的是"传感器安装和运行环境"。如果姿态估计的漂移速率增大 20%（比如从 0.5°/min 增大到 0.6°/min），最可能的根因是物理层面的变化，而不是互补滤波算法——alpha 参数和 dt 计算一旦写好不会自己退化。排查顺序：第一步查环境温度（MPU6050 的陀螺仪偏置有显著的温度系数，温度变化 10°C 可能让偏置变化 20%——如果实验环境温度不同，漂移速率自然不同，这不是故障而是物理特性）；第二步查 IMU 安装（IMU 板是否松动，减振垫是否老化——机械松动会引入额外的振动噪声，通过加速度计通道污染 theta_acc）；第三步查供电（MPU6050 的供电电压和纹波，供电噪声会直接叠加到传感器输出上）。alpha 参数是最后才查的，因为参数一旦调好不会自己变化，除非有人改了代码。模型和数据完全不相关——互补滤波是确定性算法，不涉及任何训练模型。本关正文的"先低能量验证，再逐级闭环"在这里的排查体现是：先在静止状态下重测漂移，确认退化是否可复现；如果静止时正常但运行时退化，说明问题来自振动（部署环境），而不是传感器本身。面试时的判断框架：IMU 指标退化的排查顺序是"温度 → 机械安装 → 供电 → 参数"，从最可能到最不可能；温度是最容易被忽视的因素，很多" mysteriously 退化"的 IMU 问题都是季节变化或空调开关引起的。常见误区是"漂移大就重新校准"——如果根因是温度变化，校准只在当前温度下有效，温度再变还会漂移；正确的做法是记录温度-偏置曲线，或者选用温度稳定性更好的 IMU。
<!-- /upkie-qa -->

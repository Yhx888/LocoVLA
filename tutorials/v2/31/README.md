# 31 Sim2Real 评估协议：用分布和置信区间说话

> 建设状态：可执行  
> 阶段：学习控制  
> 作品集目录：`outputs/portfolio/31`

## 岗位任务

一条策略在标称 MuJoCo 中稳定，不等于它能迁移到真实轮足机器人。质量、地面摩擦、传感器噪声、初始姿态、动作延迟与外力都会改变闭环行为。岗位上的正确问题不是“能不能 Sim2Real”，而是：在什么分布、什么任务时长、什么安全阈值和什么统计不确定度下，性能退化了多少；失败回合在哪里；下一个要补的是模型、控制器还是传感器。

本关不从零训练大模型。它固定使用 `WheelBalancerController`，在标称与随机化的 MuJoCo 分布中做配对评估。这样把“算法差异”和“物理分布差异”拆开，先建立可审计的评估协议。RL 或残差策略可以沿用同一协议，但不能因为换了模型就换掉安全指标。

## 学习目标

- 区分标称仿真、随机化仿真和真实机器，并说明 Sim2Real gap 只是对真实 gap 的代理估计。
- 读懂每回合实际采用的质量、摩擦、噪声、初始扰动、延迟和外力参数，确认配置不是“写了但没接入”。
- 用同 seed 的配对回报差与非参数 bootstrap 95% 区间报告不确定度。
- 同时报出成功率、跌倒率、最大俯仰误差与失败回合，避免平均回报掩盖安全问题。
- 能根据日志判断一个差异更可能来自动力学、感知、执行还是控制器鲁棒性。

## 前置关卡

完成 `29` 的域随机化和 `30` 的残差强化学习。第 29 关回答“如何在训练中改变分布”，本关回答“如何在改变后公平评估”。先阅读 `src/upkie_mujoco_course/envs/base_env.py`：每次 `reset(seed)` 都会把抽样后的参数写入 `info['randomization']`，不是只停留在 JSON 文件里。

## 直觉与概念

<!-- upkie-animation:31-intuition -->

把标称 MuJoCo 看作“设计图上的典型机器”，把随机化仿真看作“一小批公差不同、地面不同、传感器不同的虚拟机器”，真实机器才是未知但有限的目标分布。若只测试典型机器，结果往往过于乐观；若随机化范围凭感觉无限放大，又会把不可能的机器混进评估，失去工程意义。

本关的回合成功定义很严格也很有限：在 160 个环境步内没有触发跌倒终止，并以 `truncated=True` 到达时间上限。环境跌倒条件是俯仰误差达到 `0.8 rad` 或基座高度低于 `-0.35 m`。控制周期为 `0.01 s`，所以评估时域约 `1.6 s`。seed `29` 的峰值俯仰已到 `0.4433033573851295 rad`，仍未触发 `0.8 rad` 终止，但相对直立状态的裕量已经明显缩小。

因此，本关 `passed=true` 不等于安全认证，也不等于“所有安全指标优秀”。它只表示配对协议、随机化覆盖和统计证据满足当前自动门槛。

## 教科书级展开

<!-- upkie-animation:31-parameter -->

### 1. 写清楚评估对象和单位

本关固定对象不是神经策略，而是 `WheelBalancerController`。控制器先输出 6 维物理动作，环境接口将其归一化后执行：四个腿通道对应关节位置目标 `[rad]`，两个轮通道对应轮端力矩 `[N*m]`。状态包含俯仰 `[rad]`、速度 `[m/s]` 和高度 `[m]`。奖励是无量纲加权和，不能把回报差解释为“少了多少牛顿米”或“少了多少米”。

随机化规格如下，端点是包含式采样范围：

| 字段 | 范围 | 写入位置 | 物理意义 |
|---|---|---|---|
| `mass_scale` | `[0.90, 1.10]` | `model.body_mass` | 质量公差，无单位倍率 |
| `friction_scale` | `[0.75, 1.20]` | `model.geom_friction[:, 0]` | 接触摩擦倍率，无单位 |
| `sensor_noise_std` | `[0.001, 0.004]` | 观测向量 | 观测加性噪声，按原字段单位 |
| `initial_state_std` | `[0.002, 0.012]` | `qpos/qvel` | 初始姿态/速度扰动，混合单位，须谨慎解释 |
| `action_delay_steps` | `[0, 2]` | 动作队列 | 离散控制步，最大约 `0.02 s` |
| `push_force` | `[0.5, 1.5]` | base `xfrc_applied` | x 方向外力 `[N]` |
| `push_step` | `[35, 80]` | 控制周期索引 | 扰动开始时刻，约 `0.35-0.80 s` |
| `push_duration_steps` | `[2, 5]` | 控制周期数 | 外力持续约 `0.02-0.05 s` |

假设包括：质量和摩擦的倍率可代表主要建模误差；外力方向固定为世界 x 方向；每个回合独立；12 个种子足以给出初步区间。这些假设在轮胎打滑、结构柔顺、编码器漂移、通信丢包或真实三维地形存在时会失效，必须扩展模型或转入实机安全流程。

### 2. 为什么要做配对差

对第 `i` 个 seed，记标称和随机化回报为 `R_nominal,i` 与 `R_randomized,i`：

$$
d_{i} = R_{\text{randomized}},i - R_{\text{nominal}},i
gap = (\frac{1}{n}) \cdot sum_{i} d_{i}
$$

两组都使用 seed `23` 到 `34`，同一个 `WheelBalancerController` 也在每回合 reset。配对能消除一部分由初始伪随机序列造成的共同波动，比拿两组不相关均值相减更容易看出“分布切换”带来的变化。

`gap<0` 代表随机化条件下的平均回报较低；它不是现实世界性能的精确预测，也不自动意味着发生跌倒。必须联合成功率、跌倒率、最大俯仰和失败日志判断风险。

### 3. Bootstrap 置信区间

回报分布不必是正态。我们固定 bootstrap seed `31`，从 12 个配对差中有放回地重采样 2,000 次；每次计算均值；取 2.5% 与 97.5% 分位数：

$$
CI_{95} = [quantile_{0}.025(mean(d*)), quantile_{0}.975(mean(d*))]
$$

这里的 95% 是在重复采样近似下的区间覆盖解释，不是“随机化性能有 95% 概率正确”，更不是“实机成功率为 95%”。区间跨过零时，应报告证据不足，而不是选择更有利的单次回合；区间很宽时，优先增加独立 seed 或缩小未定义的实验变量。

### 4. 配置如何真正进入 MuJoCo

`src/upkie_mujoco_course/randomization/dynamics.py` 负责两件事：拒绝负质量、负延迟等没有物理语义的配置；用环境自己的 `np_random` 按 seed 抽取每回合参数。`BaseUpkieEnv._apply_reset_randomization()` 先恢复原始质量与摩擦，再写入本回合倍率和初始扰动。`_observation()` 读取本回合噪声，`step()` 读取本回合延迟和外力日程。

$$
randomization specification
  -> validate_{\text{randomization},\text{config}}
  -> sample_{\text{episode},\text{randomization}}(rng)
  -> reset info['randomization']
  -> mass/friction/initial state
  -> observation noise/action queue/push force
  -> per-episode \log and coverage check
$$

这条数据流很重要：如果只把随机化参数交给训练配置、却没有在环境 `reset` 和 `step` 中使用，曲线可能“看起来更鲁棒”，但实验没有改变物理条件。本关的 `configuration_coverage_ratio=1.0` 正是对八个字段实际采样的最低检查，不是对真实世界覆盖充分性的承诺。

### 5. 评估循环与失败保留

`src/upkie_mujoco_course/rl/labs.py` 的 `_rollout_classic_controller()` 每回合执行：环境 reset、控制器 reset、物理动作到归一化动作、环境 step、累计奖励、记录峰值俯仰与终止原因。无论是否跌倒，都会将该回合写入 `outputs/logs/rl_31.json`。`randomized_failure_episodes` 是显式字段；这次为空，因为 12 次都走到时间截断，下一次出现失败时不会被平均值丢掉。

适用范围是当前 Upkie 简化模型、静态平面、固定控制器和 160 步时域。它不能替代轮端电机温升、通信时延分布、实体急停、机构背隙和长期续航的硬件验证；这些属于高级硬件选修和毕业项目的安全门槛。

## 可视化证据

<!-- upkie-animation:31-evidence -->

图表告诉你性能差异出现在哪些回合和哪些质量/摩擦样本附近；日志告诉你每一个点对应什么 seed、是否跌倒、峰值俯仰是多少；测试保证固定 seed 下的采样、置信区间和证据产物可重复。请同时检查三者：

1. 若某回合回报异常低，先在日志查 `terminated`、`peak_pitch_rad` 与外力时刻。
2. 若散点图只覆盖一个质量或一个摩擦值，检查随机化采样和 reset seed，而不是先调控制器。
3. 若区间跨零，报告“当前样本不足以确认方向”，再增加回合数或改进实验设计。

## 故障诊断挑战

<!-- upkie-animation:31-comparison -->

故意把 `configs/randomization/default.json` 或传入配置中的 `action_delay_steps` 改为负数。正确行为是环境在启动时抛出含字段名的 `ValueError`；不能把负延迟解释成“预测控制”。恢复为合法值后，再检查日志的每个回合参数。

再做一个更隐蔽的错误：把 `BaseUpkieEnv.step()` 中的外力读取从 `last_randomization` 改成静态 `randomization`。现象是日志显示不同的 `push_force`，但仿真实际外力不随回合变化。最小验证是固定其他字段，只改变 `push_force` 区间，比较 `info['push_applied']`、回报分布和日志中的实际值；修复前后的实验必须使用相同 seed。

不要通过缩小随机化范围、删除失败回合或只展示最好的一次视频来“解决”差异。正确的产物是范围、失败、区间和下一步模型假设。

## 三档任务

- 基础任务：复现本关，解释回报差、区间、成功率、跌倒率和配置覆盖率为何不能互相替代。
- 岗位挑战：在不改控制器参数的前提下，将回合数增至 50，比较 12 与 50 个 seed 的区间宽度；报告运行成本、失败样本和区间是否稳定。
- 开放探索：给随机化加入一个有物理依据的新字段，例如编码器零偏或轮半径误差。先声明单位、范围、写入路径和失效条件，再修改环境与测试；不能只在 JSON 中新增一个未使用字段。

## 复盘与面试

1. 为什么此处比较的是同一 seed 的配对差，而不是两组独立平均回报？
2. 置信区间不跨零能说明什么，不能说明什么？
3. 成功率全为 1.0 但平均回报下降时，控制器可能暴露了哪些风险？
4. 如果实机跌倒而随机化仿真全部成功，你会优先排查哪些未建模因素，并如何设计一个最小复现实验？

## 复盘与面试

1. 本关最关键的假设是什么？失效时第一个可观测信号是什么？

<!-- upkie-qa:H10-q1 -->
最关键的假设是：`simulation distribution should cover measured hardware uncertainty`——即仿真中的参数随机化范围必须覆盖实机测量到的硬件不确定性。这是 Sim2Real 的核心原则：如果仿真里质量随机化范围是 ±10%，但实机测量发现实际质量偏差是 +15%，那么仿真里训练的策略从未见过 +15% 质量的情况，部署到实机上就会失效。这个假设依赖两个前提：一是硬件不确定性被正确测量（知道实际偏差是多少，而不是猜测）；二是仿真随机化的分布形状正确（不只是范围对，分布也要合理——均匀分布和高斯分布覆盖的"尾部"不同）。假设失效时，第一个可观测信号不是机器人翻倒，而是仿真和实机的行为出现系统性偏差：比如仿真里策略在 ±10% 质量偏差下都能稳定平衡，但实机上总是向一侧倾斜——这说明实际质量偏差超出了仿真覆盖范围，策略在从未见过的参数区域运行。本关正文的"先低能量验证，再逐级闭环"在这里的体现是：先在仿真里用辨识出的实机参数（而不是标称参数）运行控制律，确认仿真行为与实机观测一致，再逐步引入随机化验证鲁棒性，最后才把策略部署到实机。需要注意的是，本关当前建设状态为"规划中"，`course_checkpoint.py --chapter H10` 会明确拒绝验收。面试时的判断框架：Sim2Real 问题的排查顺序是"参数辨识准不准 → 随机化范围够不够 → 分布形状对不对"，从最容易验证的开始。常见误区是"仿真里表现好就等于实机表现好"——仿真和实机之间永远存在差距（reality gap），Sim2Real 的目标不是消除差距，而是让仿真覆盖差距的范围。
<!-- /upkie-qa -->

2. 为什么当前接口、单位和限幅这样设计？有哪些可替代方案？

<!-- upkie-qa:H10-q2 -->
`simulation distribution should cover measured hardware uncertainty` 的接口设计把"测量"和"仿真"连接起来：参数辨识的输出（实机测量的质量、摩擦系数、电机 Kt 等，各有测量不确定度）直接作为仿真随机化范围的输入。单位必须全程 SI（kg、m、N·m、rad/s），与课程软件部分（第 38 章的状态向量、第 29/31 章的域随机化配置）保持一致，避免单位换算引入的覆盖范围错误。限幅设计：随机化范围不是越大越好——范围太大会让策略在仿真里见到物理上不可能的参数组合（比如质量为负、摩擦系数 >2），浪费训练资源且可能引入不稳定的策略行为；范围应该基于测量不确定度（比如质量测量值 2.0 kg ± 0.1 kg，随机化范围设为 [1.9, 2.1] kg，而不是 [0, 10] kg）。本关正文要求"所有物理量使用 SI 单位"，参数辨识的输出格式应该包含"标称值 + 不确定度"（比如 `mass = 2.0 ± 0.1 kg`），而不只是标称值，这样仿真随机化范围才有依据。替代方案：用系统辨识的置信区间直接设定随机化范围（比手动设定更严格，但需要足够多的辨识实验）；或者用自适应控制在线估计参数偏差（不需要预先知道不确定性范围，但增加了控制系统的复杂度）；或者用鲁棒控制（H∞）直接设计对参数不确定性不敏感的控制器（不需要随机化，但保守性更强，性能上限更低）。需要注意的是，本关当前为规划中状态，具体的辨识参数和随机化范围尚未确定。面试时的判断框架：Sim2Real 接口设计的核心问题是"仿真里的不确定性范围有没有物理依据"，拍脑袋设定的范围不如测量出来的范围可信。常见误区是"随机化范围越大策略越鲁棒"——范围超出物理可能时，策略在学习应对不可能情况，反而在真实情况下表现更差。
<!-- /upkie-qa -->

3. 你能用哪三份证据证明结果可复现？

<!-- upkie-qa:H10-q3 -->
Sim2Real 的可复现性证据需要覆盖"参数辨识、仿真验证、实机对比"三个层次。第一份是参数辨识记录：每个辨识参数的测量方法、测量次数、标称值和不确定度（比如"质量：用电子秤测量 5 次，均值 2.03 kg，标准差 0.02 kg"）；这是仿真随机化范围的物理依据，让别人能用同样的测量方法重测得到相近的参数值。第二份是仿真验证记录：在辨识参数下运行的仿真控制性能（平衡时间、稳态误差、扰动恢复），以及与标称参数下性能的对比；这是"仿真是否反映了实机"的验证，如果辨识参数下的仿真行为与实机观测差距很大，说明辨识不完整（有未辨识的参数或建模误差）。第三份是实机对比记录：实机控制性能与仿真预测的对比（同一控制律、同一扰动条件下），量化 Sim2Real gap（比如"仿真预测恢复时间 0.5 s，实机测量 0.6 s，gap 20%"）；这是 Sim2Real 最终是否成功的直接证据，gap 越小说明仿真覆盖越充分。三份证据的分工：辨识记录回答"参数准不准"，仿真记录回答"仿真像不像"，实机记录回答"差距有多大"。需要注意的是，本关当前为规划中状态，这三份证据的具体格式和验收标准尚未建立。面试时的判断框架：Sim2Real 证据的可复现性依赖固定的实机状态——电池电量、机械磨损、环境温度都会影响实机性能，不记录这些条件的对比数据没有可比性。常见误区是"仿真和实机数字一样就等于 Sim2Real 成功"——单次对比一致可能是碰巧，需要在多种扰动条件下重复对比，统计 gap 的分布而不是单点值。
<!-- /upkie-qa -->

4. 如果指标退化 20%，你先查模型、数据、控制还是部署？为什么？

<!-- upkie-qa:H10-q4 -->
这次的答案和前几关不同：先查模型，具体说是查"仿真模型参数是否还反映实机"。如果 Sim2Real gap 从 10% 退化到 30%（实机性能比仿真预测差 30%），最可能的根因是仿真模型参数与实机的偏差增大了——硬件会随时间变化：机械磨损改变摩擦系数，电池老化改变供电电压，舵机齿轮磨损改变关节间隙（H07 章），这些变化让实机参数偏离了最初辨识的值，但仿真里还在用旧参数。排查顺序：第一步重新辨识关键参数（质量、摩擦系数、电机 Kt，与 H10 参数辨识记录对比，看偏差是否增大）；第二步检查仿真随机化范围是否还覆盖当前实机参数（如果实机摩擦系数从 0.5 变成了 0.3，而仿真随机化范围是 [0.45, 0.55]，那么当前实机参数已经在仿真覆盖范围之外了）；第三步才查控制律（如果参数辨识和随机化范围都没问题，但 gap 仍然大，说明有未建模的动态——比如结构柔性、传感器延迟，这些在仿真里没有建模）。部署（网络、供电）在 Sim2Real gap 问题里是次要因素——除非供电电压变化导致执行器参数改变，但那属于参数辨识问题，不是部署问题。本关正文的"先低能量验证，再逐级闭环"在这里的排查体现是：先在仿真里用当前实机辨识参数重跑，确认仿真行为是否更新了；如果更新后 gap 缩小，说明根因是参数漂移，需要扩大随机化范围或增加在线适应。面试时的判断框架：Sim2Real gap 退化的排查顺序是"参数漂移 → 随机化范围 → 未建模动态"，从最可能到最不可能；硬件参数随时间漂移是最常见的根因，尤其是机械磨损和电池老化。常见误区是"gap 大就重新训练策略"——如果根因是参数漂移，重新训练只是在新参数上拟合，参数继续漂移还会再退化；正确的做法是扩大随机化范围覆盖参数漂移的预期范围，或者加入在线参数适应。
<!-- /upkie-qa -->

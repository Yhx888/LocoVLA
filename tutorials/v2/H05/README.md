## 复盘与面试

1. 本关最关键的假设是什么？失效时第一个可观测信号是什么？

<!-- upkie-qa:H05-q1 -->
最关键的假设是：AS5600 编码器输出的角度 `theta_k` 是转子真实机械角度的无偏估计，且相邻两帧的差值 `theta_k - theta_{k-1}` 经过 unwrap 后能正确反映实际转动量。本关正文的核心关系 `omega = unwrap(theta_k - theta_{k-1}) / dt` 依赖两个前提：一是采样周期 dt 已知且恒定（dt 的误差直接等比例传递到角速度 omega）；二是角度分辨率足够（AS5600 是 12 位编码器，分辨率 360°/4096 ≈ 0.088°，在低速时相邻帧角度差可能小于分辨率，unwrap 后的差值被量化噪声主导）。假设失效时，第一个可观测信号是角速度估计出现异常：如果磁钢安装偏心或气隙过大，theta_k 会叠加周期性误差（每转一圈出现一次正弦波动），omega 里会出现与转速同频的纹波；如果 I2C 通信受到干扰，theta_k 可能出现跳变（比如从 359° 突然跳到 0°），unwrap 逻辑如果处理不当会产生一个虚假的大角度差，omega 出现尖峰。本关正文的"先低能量验证，再逐级闭环"在这里的体现是：先手动缓慢转动电机，确认角度读数连续且方向正确，再低速运行确认 omega 估计合理，最后才进入 FOC 闭环（H04 章）。需要注意的是，本关当前建设状态为"规划中"，`course_checkpoint.py --chapter H05` 会明确拒绝验收。面试时的判断框架：编码器问题的排查顺序是"机械安装 → 通信质量 → 信号处理"，大多数角度误差来自机械安装（偏心、气隙），而不是电子噪声。常见误区是"角度跳变就加滤波"——如果跳变来自通信干扰，滤波只能掩盖症状；如果跳变来自 unwrap 逻辑错误，滤波会让问题更难发现。
<!-- /upkie-qa -->

2. 为什么当前接口、单位和限幅这样设计？有哪些可替代方案？

<!-- upkie-qa:H05-q2 -->
`omega = unwrap(theta_k - theta_{k-1}) / dt` 用 rad/s 作为角速度单位，与课程软件部分的状态向量（第 38 章的 `[m, m/s, rad, rad/s]`）保持一致，避免单位换算引入的错误。unwrap 的必要性来自角度的周期性：AS5600 输出 0~2π 的绝对角度，当转子从 359° 转到 1° 时，原始差值是 -358°，但实际转动是 +2°；unwrap 通过判断差值是否超过 ±π 来修正这个跳变，把 -358° 修正为 +2°。dt 用秒（s）而不是毫秒，是因为 rad/s 是 SI 单位，dt 必须用秒才能得到正确的 rad/s；如果 dt 用毫秒而忘记换算，omega 会偏大 1000 倍，FOC 的速度环会完全失控。限幅设计：omega 的最大值受电机机械转速限制（比如最大 10000 RPM ≈ 1047 rad/s），超过这个值的 omega 估计一定是噪声或通信错误，应该被拒绝或触发故障标志。替代方案：用霍尔传感器（分辨率低，每转只有 6 个脉冲，但成本极低，适合低速大扭矩应用）；或者用增量式光电编码器（分辨率极高，但需要参考点回零，断电后位置丢失）；AS5600 的磁编码方案在分辨率、成本和绝对位置保持之间取得了较好的平衡，适合本课程的小型轮足机器人。需要注意的是，本关当前为规划中状态，具体的 dt 值和 omega 限幅尚未确定。面试时的判断框架：编码器接口设计的核心问题是"分辨率够不够（低速时）"和"带宽够不够（高速时）"，两者往往相互制约。常见误区是"分辨率越高越好"——高分辨率编码器在低速时确实更精确，但在高速时 I2C 带宽可能成为瓶颈（AS5600 的 I2C 最大 1MHz，采样率受限）。
<!-- /upkie-qa -->

3. 你能用哪三份证据证明结果可复现？

<!-- upkie-qa:H05-q3 -->
编码器标定的可复现性证据需要覆盖"静态精度、动态精度、通信鲁棒性"三个层次。第一份是静态精度记录：在多个已知机械角度（比如每 30° 一个点，共 12 个点）下读取 AS5600 的输出，计算每个点的误差（读数 - 真实角度）和最大误差；这是标定质量的直接证据，让别人能用同样的夹具和量具重测得到相近的误差分布。第二份是动态精度记录：以已知恒定转速（比如用另一个已标定的编码器作为参考）转动电机，比较 AS5600 估计的 omega 与参考值的偏差，记录均值误差和纹波幅度；这是 `omega = unwrap(theta_k - theta_{k-1}) / dt` 这个公式在实际运行中的验证。第三份是通信鲁棒性记录：在 I2C 线缆附近引入干扰源（比如电机 PWM 驱动线），记录 theta_k 出现跳变的频率和幅度，验证 unwrap 逻辑和异常值检测是否正确处理了这些干扰；这是边界行为的证据，证明编码器在实际电磁环境下不会给出危险的错误角度。三份证据的分工：静态记录回答"角度读数准不准"，动态记录回答"速度估计准不准"，鲁棒性记录回答"干扰下会不会出错"。需要注意的是，本关当前为规划中状态，这三份证据的具体格式和验收标准尚未建立。面试时的判断框架：编码器证据的可复现性依赖固定的机械安装条件——磁钢位置、气隙、线缆走线都会影响测量结果，不记录这些条件的标定数据没有可比性。常见误区是"只测静态精度"——静态精度好不代表动态精度好，I2C 通信延迟在高速时会引入相位滞后，静态测试完全发现不了这个问题。
<!-- /upkie-qa -->

4. 如果指标退化 20%，你先查模型、数据、控制还是部署？为什么？

<!-- upkie-qa:H05-q4 -->
先查部署，在编码器语境下对应的是"机械安装和电气连接"。如果角速度估计的纹波增大 20%（比如从 ±5 rad/s 增大到 ±6 rad/s），最可能的根因是机械或电气层面的变化，而不是信号处理算法——unwrap 逻辑和 dt 计算一旦写好不会自己退化。排查顺序：第一步查磁钢安装（磁钢是否松动或偏移，气隙是否增大——气隙增大会降低信号幅度，增加角度噪声；磁钢偏心会引入每转一次的周期性误差，在 omega 里表现为与转速同频的纹波）；第二步查 I2C 连接（接插件是否氧化、线缆是否靠近电机驱动线——PWM 开关噪声耦合进 I2C 会导致偶发的通信错误，theta_k 出现随机跳变，omega 出现尖峰）；第三步查供电（AS5600 的供电电压是否在规格范围内，供电纹波是否过大——供电噪声会直接叠加到角度输出上）。信号处理参数（dt、滤波系数）是最后才查的，因为这些参数一旦确定不会自己变化。模型和数据完全不相关——编码器标定是物理测量，不涉及任何训练模型。本关正文的"先低能量验证，再逐级闭环"在这里的排查体现是：先断开电机驱动（消除 PWM 干扰源），手动缓慢转动电机，确认角度读数本身正常；如果断开驱动后纹波消失，说明干扰来自电机驱动线，需要重新布线或加屏蔽。面试时的判断框架：编码器信号退化的排查顺序是"机械 → 电磁干扰 → 供电 → 信号处理"，从最可能到最不可能。常见误区是"纹波大就加数字滤波"——滤波会降低带宽、引入相位滞后，如果根因是磁钢松动，滤波只是掩盖了机械故障，松动会继续恶化直到编码器完全失效。
<!-- /upkie-qa -->

## 复盘与面试

1. 本关最关键的假设是什么？失效时第一个可观测信号是什么？

<!-- upkie-qa:H02-q1 -->
最关键的假设是：机械加工的实际尺寸可以用 `clearance = hole_size - shaft_size` 这个确定性关系描述，且公差在装配前可以被测量和预判。这个假设失效时（比如加工件的实测尺寸超出图纸公差带），第一个可观测信号不是机器人运行异常，而是装配阶段的物理反馈：轴和孔的配合出现明显间隙（clearance 过大，部件晃动）或过盈（clearance 为负，无法装配）。本关正文的核心定位是"硬件把每个软件假设变成电流、温度、公差和风险；先低能量验证，再逐级闭环"——这意味着公差问题的验证顺序是：先用量具（卡尺、千分尺）测量单个零件尺寸，再做试装配验证配合，最后才上电运行；不能跳过测量直接装配，更不能跳过装配直接上电。需要注意的是，本关当前建设状态为"规划中"，`course_checkpoint.py --chapter H02` 会明确拒绝验收——这本身就是对"假设尚未被验证"的诚实处理：在加工和测量流程没有建立之前，不应该给出"通过"的结论。面试时的判断框架：硬件假设的验证成本远高于软件假设，所以验证顺序必须是"低成本测量 → 试装配 → 低能量运行 → 全功率运行"，任何跳步都是在把风险后移。常见误区是"图纸标注了公差就等于加工件一定在公差内"——图纸是设计意图，加工件是物理现实，两者之间的差距就是质量检验存在的理由。
<!-- /upkie-qa -->

2. 为什么当前接口、单位和限幅这样设计？有哪些可替代方案？

<!-- upkie-qa:H02-q2 -->
`clearance = hole_size - shaft_size` 用毫米（mm）作为单位，正值表示间隙配合（轴可以在孔内转动），负值表示过盈配合（轴和孔压配合，靠摩擦力传递扭矩），零表示过渡配合。这个符号约定直接对应装配行为：设计轮轴配合时，需要转动的关节用正间隙（比如 0.02~0.05 mm），需要固定连接的部位用过盈（比如 -0.01~-0.03 mm）。本关正文强调"所有物理量使用 SI 单位"，机械加工里 mm 是事实标准（图纸标注、量具读数、加工机床输入都用 mm），强行用 m 会引入不必要的小数位和换算错误。"先低能量验证，再逐级闭环"是本关的核心限幅思想：不是直接上满电压运行，而是先手动转动关节检查机械配合，再用低电压（比如额定电压的 10%）验证电机方向，最后才逐步升到工作电压。替代方案：用角度公差（弧度）描述旋转关节的配合精度，这在需要精确角度定位的场合（比如编码器安装）更直接，但测量难度更大（需要角度仪而不是卡尺）。需要注意的是，本关当前为规划中状态，具体的公差数值和配合规格尚未确定，上述分析基于通用的机械设计原则和本关已声明的核心关系。面试时的判断框架：机械接口设计的核心问题是"这个配合需要传递什么（扭矩、位置、还是只支撑）"，传递需求决定配合类型，配合类型决定公差带。常见误区是"公差越小越好"——公差越小加工成本越高，0.01 mm 公差的成本可能是 0.1 mm 公差的十倍以上，设计时要在功能和成本之间取平衡。
<!-- /upkie-qa -->

3. 你能用哪三份证据证明结果可复现？

<!-- upkie-qa:H02-q3 -->
机械加工的可复现性证据与软件实验不同，需要覆盖"测量、装配、运行"三个阶段。第一份是尺寸测量记录：每个关键配合面的实测尺寸（孔径、轴径、计算得到的 clearance），用量具型号、测量人员、测量日期标注；这是最基础的证据，让别人能用同样的量具在同样的位置重测得到相近的数值（测量误差在量具精度范围内）。第二份是装配验证记录：试装配时的配合手感（间隙/过盈/过渡）、是否需要工具压入、装配后关节的转动阻力；这是定性但关键的证据，尺寸合格但装配失败说明公差设计或加工质量有问题。第三份是低能量运行记录：低电压下电机转动方向、电流波形、温升，确认机械配合在运动状态下没有异常摩擦或卡滞；本关正文的"先低能量验证，再逐级闭环"就是这份证据的方法论依据。三份证据的分工：测量记录回答"零件尺寸对不对"，装配记录回答"配合行为对不对"，运行记录回答"运动状态下有没有问题"。需要注意的是，本关当前为规划中状态，这三份证据的具体格式和验收标准尚未建立，`course_checkpoint.py --chapter H02` 会明确拒绝验收。面试时的判断框架：硬件证据的可复现性比软件更难保证（同一批加工件的尺寸有散布），所以硬件证据必须记录测量条件和样本数量，不能只记录"通过/失败"。常见误区是"装配成功就等于设计正确"——装配成功只证明这批零件的配合可以，不能证明公差设计对所有加工散布都安全。
<!-- /upkie-qa -->

4. 如果指标退化 20%，你先查模型、数据、控制还是部署？为什么？

<!-- upkie-qa:H02-q4 -->
先查"部署"——在硬件语境下，部署对应的是加工和装配环节，而不是软件环境。如果关节转动阻力增大 20%（比如从 0.1 N·m 增到 0.12 N·m），最可能的根因是机械配合出了问题，而不是控制律或传感器。排查顺序：第一步查加工件尺寸（用卡尺重测孔径和轴径，计算 clearance 是否还在设计公差带内）——如果 clearance 变小甚至变负，说明加工件尺寸超差，或者不同批次的加工件混用了；第二步查装配（是否有异物进入配合面、润滑是否充分、紧固件是否过紧导致结构变形）；第三步查运行环境（温度变化导致金属热胀冷缩，高温下间隙变小、阻力增大）。模型和数据在硬件公差问题里几乎不相关——控制律（第 38 章的 PD 增益）不会因为机械配合变紧而改变，传感器数据（IMU、编码器）也不会因为公差问题而失效（除非机械卡滞导致编码器读数异常，但那是第二步才能发现的次级现象）。本关正文的"先低能量验证，再逐级闭环"就是这类排查的方法论：在低能量下发现问题（阻力增大、电流异常）比在全功率下发现问题（电机过热、结构损坏）成本低得多。面试时的判断框架：硬件指标退化的排查顺序是"机械 → 电气 → 软件"，与软件系统正好相反；软件工程师转硬件最常见的错误是一上来就怀疑代码，而实际上机械问题占了硬件故障的大多数。常见误区是"阻力增大就加大控制力矩"——这掩盖了机械问题，可能导致电机过载或结构损坏。
<!-- /upkie-qa -->

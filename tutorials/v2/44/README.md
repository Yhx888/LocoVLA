## 直觉与概念

毕业项目不是功能拼盘，而是一条从需求到证据、从故障到复盘的完整工程链。

本关核心问题是：**如何用可测量证据判断"系统设计与接口评审"已经达到岗位可用，而不是只在一次演示中碰巧工作？**

### 为什么需要设计文档

| 动机 | 没有设计文档的后果 | 有设计文档的好处 |
|---|---|---|
| 可维护性 | 接口改动后无人知道全貌，改一处崩三处 | 改接口前先改文档，文档与代码一致性由测试守护 |
| 可审计性 | 出了故障无法追溯"设计时是否考虑过这个风险" | FMEA 风险矩阵留下设计思考痕迹，故障可对照排查 |
| 知识传承 | 新人接手只能读代码猜意图 | 文档讲清"为什么这样设计"，新人能独立理解 |

## 教科书级展开

### 四层链路详解

核心关系：

需求层 → 接口层 → 风险层 → 验证证据层

每一层为上一层提供可验证证据，下层不能跳过上层直接依赖：

| 层 | 回答的问题 | 本关交付物 |
|---|---|---|
| 需求层 | 系统要做什么？安全约束是什么？ | `system_design.md` §1（岗位能力矩阵 + 安全要求） |
| 接口层 | 模块之间怎么通信？单位/坐标系/限幅是什么？ | `system_design.md` §2 + `interface_contract.md` 全文 |
| 风险层 | 哪些故障会发生？怎么检测？怎么制动？ | `system_design.md` §3（FMEA 8 条 + 风险矩阵） |
| 验证证据层 | 怎么证明系统满足上述设计？ | `system_design.md` §4（测试矩阵 + 结果契约） |

### 接口契约要素

接口契约文档（`interface_contract.md`）必须为每个接口说明以下要素：

| 要素 | 话题示例 | 服务示例 | 参数示例 |
|---|---|---|---|
| 名称 | `/imu` | `/estop` | `pitch_safety_limit` |
| 类型 | `sensor_msgs/Imu` | `std_srvs/Trigger` | `double` |
| 方向/QoS | 输入 / SensorDataQoS | — | — |
| 单位 | rad/s | — | rad |
| 范围/限幅 | `[-1.0, 1.0] × 2` | — | `[0.1, 0.5]` |
| 坐标系 | 机身坐标系 | — | — |

### FMEA 方法

故障模式与影响分析（FMEA）按六列展开：

故障现象 → 第一处异常证据 → 检测延迟 → 制动延迟 → 最终状态 → 纠正动作

本关 FMEA 列出 8 种故障（F-01 到 F-08），按"严重度 × 发生概率"评级风险等级（高/中/低），并给出 mitigation 优先级排序。

阅读公式或契约时按七层顺序检查：直觉、符号、物理意义、设计动机、逐步推导、数值算例、代码映射。所有物理量使用 SI 单位；离散时间量必须说明采样周期。该关系默认模型字段、坐标方向和执行器语义与 `configs/robot/upkie.json` 一致。

适用范围是当前关卡声明的平衡点、约束和数据分布。接触丢失、传感器过期、动作饱和、输入超出训练分布或公式假设不成立时，必须进入诊断/安全路径，不能继续外推。

数值算例从配置中取一组实际参数，手算一个时间步，再与代码输出逐项对齐。若两者不同，优先检查单位、左右轮方向、平衡点和数组顺序。

## 故障诊断挑战

故意制造一个与"系统设计与接口评审"直接相关的错误：

1. 打开 `docs/design/interface_contract.md`，删除 `/safety_state` 话题所在行；
2. 运行 `pytest tests/test_design_docs.py -q`；
3. 观察 `test_interface_contract_covers_topics` 失败，失败信息提示 `interface_contract.md 缺少话题：['/safety_state']`；
4. 恢复文档，重新运行测试确认通过。

按"现象 → 第一处异常证据 → 根因假设 → 最小验证 → 修复后对比"记录，不允许通过放宽阈值隐藏失败。

## 复盘与面试

1. 本关最关键的假设是什么？失效时第一个可观测信号是什么？
   - 假设：文档与代码接口一一对应。失效信号：`test_design_docs.py` 中接口覆盖测试失败。
2. 为什么当前接口、单位和限幅这样设计？有哪些可替代方案？
   - 轮端用 N·m 力矩而非速度控制：力矩限幅可直接守护安全边界；速度控制需要额外限速逻辑。QoS 用 SensorDataQoS：IMU 高频丢包优于堆积。
3. 你能用哪三份证据证明结果可复现？
   - 设计评审报告（接口覆盖矩阵全 ✓）、结果契约（`passed=true`）、8 个 pytest 全过。
4. 如果指标退化 20%（如覆盖率降到 80%），你先查模型、数据、控制还是部署？为什么？
   - 先查部署（C++ 代码是否新增了未文档化的接口），因为覆盖率下降的直接原因是代码与文档脱节，而非模型或数据问题。

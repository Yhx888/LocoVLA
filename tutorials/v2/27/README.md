## 岗位任务

你接到的不是“把 PPO 跑起来”的任务，而是一次训练异常复盘：同一个策略有时更新后更好，有时更差。控制工程师必须回答三个问题：状态、动作、奖励和终止是否构成了明确的 MDP；梯度的方向有没有统计偏差；加入优势或价值基线后，到底减少了多少随机性。

本关先在一个可以手算答案的一维高斯策略中验证策略梯度，再把结论映射回 Upkie 的 Gymnasium 环境。这样做的原因很朴素：如果一个算法在答案已知的最小实验中都无法通过，就没有理由相信它在含接触、延迟和跌倒终止的机器人中“学会了”。

## 学习目标

- 用自己的话说明一个 MDP 的状态 `s`、动作 `a`、转移 `p(s'|s,a)`、奖励 `r` 和终止条件分别承担什么职责。
- 从高斯分布与期望回报出发，推导 REINFORCE 的梯度，并说明为什么减去与动作无关的基线不会改变期望。
- 用固定 seed 复现解析梯度、普通 REINFORCE 梯度和带价值基线的梯度。
- 解释本关图表中的“均值接近真值”和“方差更小”是两项不同的验收，不把其中一项误当成另一项。
- 把策略梯度的输入、动作限幅、奖励、终止和日志字段定位到 Upkie 工程的实际代码。

## 直觉与概念

<!-- upkie-animation:27-intuition -->

### 把机器人任务写成 MDP

对 Upkie，时刻 `t` 的状态可以理解为“做决定时可见的、会影响下一步的摘要”。在当前实现中，观测含俯仰误差 `[rad]`、俯仰角速度 `[rad/s]`、机身高度 `[m]`、位置 `[m]`、前向速度 `[m/s]`、四个腿关节位置/速度和两个轮速。动作是六个归一化数，经过 `to_physical_action()` 变为四个腿部位置目标 `[rad]` 与两个轮端力矩 `[N*m]`。一个控制周期由模型配置的 `frame_skip * timestep` 决定，环境每次 `step()` 都给出奖励、跌倒终止和时长截断。

关键假设是：观测足以近似刻画对下一步有用的历史。传感器延迟、接触模式没有被观测到、或随机化参数隐含地改变了动力学时，这个假设会变弱，问题更接近 POMDP。工程上不要通过“把状态名字改成 MDP”掩盖这个事实，而要记录延迟、噪声和估计器设计。

### 为什么需要概率策略

确定性控制器在同一状态永远给相同动作；随机策略还会描述“这次尝试什么附近的动作”。本关使用最小但可解析的策略：

a ~ Normal(mu, sigma^2)
- `$mu` — 0.15                    无量纲归一化动作
- `$sigma` — 0.45                 无量纲探索标准差
r(a) = -(a - 0.65)^2        无量纲即时回报

它不是 Upkie 的物理模型，而是策略梯度单元测试：动作与回报都没有 SI 单位，目的是隔离统计问题。真实 Upkie 中动作会被限幅成位置 `[rad]` 与力矩 `[N*m]`，奖励由直立、能耗、位置和光滑性项组成，不能把本关的 `0.65` 当成任何机器人参数。

## 教科书级展开

<!-- upkie-animation:27-parameter -->

### 1. 目标函数与符号

令 `theta=mu`，期望回报为：

$$
J(\mu) = E_{a}[r(a)]
      = -E[(a - 0.65)^2]
      = -((\mu - 0.65)^2 + \sigma^2)
$$

- `J`：期望回报，无量纲。
- `mu`：高斯均值，也是要优化的策略参数，无量纲。
- `sigma`：固定探索标准差，无量纲，且必须大于零。
- 公式假设样本独立、奖励二阶矩存在、`sigma` 不随 `mu` 变化。

本关 `mu=0.15`、`sigma=0.45`，所以：

$$
dJ/dmu = -2(\mu - 0.65) = -2(-0.50) = 1.0
$$

正号的物理直觉是：当前均值在目标左边，增大均值能让动作更接近 `0.65`。如果动作饱和、奖励不可导、或通过环境产生的样本不再独立，不能直接把这个手算结论外推。

### 2. 从概率密度得到 REINFORCE

高斯对数概率的均值梯度为：

$$
grad_{\mu} \log pi_{\mu}(a) = (a - \mu) / \sigma^2
$$

代入对数导数技巧：

$$
grad J(\mu)
= grad ∫ pi_{\mu}(a) r(a) da
= ∫ pi_{\mu}(a) grad \log pi_{\mu}(a) r(a) da
= E[grad \log pi_{\mu}(a) r(a)]
$$

这里没有对环境动力学求导，因此它可以处理 MuJoCo 中的接触与终止；代价是方差较大。代码中的 `score=(actions-mean)/(std*std)` 对应上式，`reward=-(actions-target_action)**2` 对应回报，随后对每批 128 个样本求平均。

### 3. 为什么可以减去价值基线

取任意不依赖当前动作 `a` 的常数或状态函数 `b`：

$$
E[grad \log \pi(a) \cdot b]
= b * ∫ \pi(a) grad \log \pi(a) da
= b \cdot grad ∫ \pi(a) da
= b \cdot grad 1
= 0
$$

因此 `r(a)` 换成优势 `A(a)=r(a)-b` 不会改变梯度期望。本实验使用解析状态价值：

$$
b = E[r(a)] = -((\mu - 0.65)^2 + \sigma^2) = -0.4525
$$

注意“不会改变期望”不等于“任何基线都必然降方差”。基线选得差、由同一动作泄漏信息、或被错误地反向传播到策略参数，都可能引入额外方差或偏差。PPO 的价值网络是近似基线，必须单独观察其误差和训练稳定性。

### 4. 数值算例与代码映射

`src/upkie_mujoco_course/rl/labs.py` 的 `estimate_gaussian_policy_gradient()` 先用 `np.random.default_rng(seed)` 生成形状为 `(320, 128)` 的动作。每一行是一项独立的小批量实验；每行均值就是一次可能的梯度更新方向。它同时计算：

```python
raw_gradients = np.mean(score * reward, axis=1)
baseline_gradients = np.mean(score * (reward - value_baseline), axis=1)
```

不要把这一段复制到真实控制循环：真实策略的 `log_prob` 来自神经网络分布，`reward` 来自环境回合，`value_baseline` 来自只看状态的价值函数。这里保留显式数组，是为了让你能逐项打印、手算和定位错误。

### 5. 从最小实验回到 Upkie 数据流

reset(seed)
-> 观测 s_t
-> 策略给出归一化动作 a_t
-> to_physical_action: [rad, rad, rad, rad, N*m, N*m]
-> MuJoCo step
-> reward / terminated / truncated / info
-> 轨迹上的 return 与 advantage
-> 策略梯度更新

`src/upkie_mujoco_course/envs/base_env.py` 是这条链路的事实源：它处理执行器限幅、噪声、动作延迟、外力、奖励和跌倒终止。`src/upkie_mujoco_course/rl/train_sb3.py` 才负责把该环境交给 SB3 PPO。若观测维度、动作语义或终止条件改变，应先更新环境测试与课程契约，再谈训练曲线。

## 故障诊断挑战

<!-- upkie-animation:27-comparison -->

故意把 `score` 写成 `(actions-mean)/std`，再运行一个副本。现象通常是梯度均值随 `sigma` 被错误缩放；第一处证据是它偏离解析梯度 `1.0`。按以下路径诊断：

1. 在日志确认 `sigma=0.45` 与动作样本范围正常。
2. 手算高斯对数概率的一阶导数，检查分母应为 `sigma^2` 而不是 `sigma`。
3. 只修复 score 项，保持 seed、样本量和奖励函数不变。
4. 比较修复前后绝对误差和直方图中心，不要通过增大验收阈值掩盖问题。

另一个常见错误是让基线依赖当前动作，例如使用 `b=r(a)`；这样优势恒为零，梯度也会错误地消失。价值基线可以依赖状态和历史估计，不能偷看本次被评估的动作回报。

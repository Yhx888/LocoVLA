## 复盘与面试

1. 本关最关键的假设是什么？失效时第一个可观测信号是什么？

<!-- upkie-qa:H04-q1 -->
最关键的假设是：`tau ≈ Kt × Iq` 这个线性关系成立——即电机输出力矩与 q 轴电流成正比，比例系数 Kt（力矩常数）是已知且恒定的。这个假设依赖两个前提：一是 FOC 的电角度估计正确（知道转子磁场方向，才能把电流分解到 d/q 轴）；二是电机工作在线性区（磁路未饱和，Kt 不随电流变化）。假设失效时，第一个可观测信号不是力矩为零，而是电机行为异常：如果电角度估计错误（比如编码器零点标定偏差，H05 章的内容），FOC 会把电流注入错误的轴，电机表现为抖动、反转或无力——此时 Iq 的设定值可能完全正确，但实际力矩方向错误。如果磁路饱和（电流过大），Kt 下降，实际力矩小于 `Kt × Iq` 的预期，电机"软"——给同样的电流指令，加速度比预期小。本关正文的"先低能量验证，再逐级闭环"在这里的具体体现是：先用低电流（比如额定电流的 10%）验证电机转动方向正确，再逐步增大电流验证力矩线性度，最后才进入闭环控制。需要注意的是，本关当前建设状态为"规划中"，`course_checkpoint.py --chapter H04` 会明确拒绝验收。面试时的判断框架：FOC 问题的排查顺序是"电角度 → 电流环 → 速度环 → 位置环"，从内环到外环；电角度错误是最常见也最危险的故障，因为它会让所有外环控制都建立在错误的基础上。常见误区是"电机不转就加大电流"——如果电角度错误，加大电流只会让电机更剧烈地抖动或反转，而不是转起来。
<!-- /upkie-qa -->

2. 为什么当前接口、单位和限幅这样设计？有哪些可替代方案？

<!-- upkie-qa:H04-q2 -->
`tau ≈ Kt × Iq` 的单位是 N·m = (N·m/A) × A，Kt 的单位 N·m/A 直接告诉你"每安培 q 轴电流产生多少力矩"，这是 FOC 控制里最核心的物理量。FOC 用电角度（rad，电角度 = 机械角度 × 极对数）控制 q 轴电流，而不是直接控制相电流，原因是：三相电机的相电流是交流量（随转子转动而变化），控制交流量需要极高的带宽；经过 Park 变换到 d/q 坐标系后，Iq 是直流量，可以用简单的 PI 控制器精确控制。限幅设计有两层：电流限幅（Iq 最大值，防止磁路饱和和过热）和电压限幅（PWM 占空比上限，受供电电压限制，H03 章的供电电压决定了最大可用电压）。本关正文要求"所有物理量使用 SI 单位"，电角度用 rad 而不是度，角速度用 rad/s 而不是 RPM，与课程软件部分（第 38 章的状态向量 `[m, m/s, rad, rad/s]`）保持单位一致。替代方案：无传感器 FOC（通过反电动势估计电角度，不需要编码器），成本更低但在低速和静止时估计精度差，不适合需要零速保持力矩的平衡控制；或者用梯形波驱动（BLDC 六步换向）代替 FOC，实现简单但力矩脉动大，不适合需要平滑力矩的精密控制。需要注意的是，本关当前为规划中状态，具体的 Kt 值、电流限幅和 PWM 频率尚未确定。面试时的判断框架：FOC 接口设计的核心问题是"控制什么量（Iq）、用什么反馈（电角度）、限幅在哪里（电流和电压）"，三者缺一不可。常见误区是"FOC 一定比六步换向好"——对于风扇、水泵等不需要精密力矩控制的应用，六步换向的成本优势更明显。
<!-- /upkie-qa -->

3. 你能用哪三份证据证明结果可复现？

<!-- upkie-qa:H04-q3 -->
FOC 控制的可复现性证据需要覆盖"开环验证、闭环性能、边界行为"三个层次。第一份是开环验证记录：在固定电角度下注入固定 Iq（比如 0.1A），测量电机输出力矩（用扭力计或已知惯量的加速度推算），验证 `tau ≈ Kt × Iq` 的线性关系；这是最基础的证据，证明 FOC 的坐标变换和电角度估计是正确的。第二份是闭环性能记录：速度环或力矩环的阶跃响应（设定值突变后的超调量、 settling 时间、稳态误差），在固定负载和固定供电电压下测量；这是控制性能的量化证据，让别人能在相同条件下重测得到相近的动态响应。第三份是边界行为记录：电流限幅触发时的行为（Iq 达到限幅值后力矩是否停止增长）、电压饱和时的行为（PWM 占空比达到 100% 后速度是否还能增加）、过流保护触发时的行为（电源是否切断、电机是否安全停止）；这是安全边界的证据，证明限幅设计在实际上电时确实生效。三份证据的分工：开环记录回答"FOC 基本原理对不对"，闭环记录回答"控制性能好不好"，边界记录回答"安全保护有没有"。需要注意的是，本关当前为规划中状态，这三份证据的具体格式和验收标准尚未建立。面试时的判断框架：FOC 证据的可复现性依赖固定的机械负载和供电条件——同一个电机在空载和带载下的阶跃响应完全不同，不记录负载条件的性能数据没有可比性。常见误区是"只测稳态性能"——稳态误差小不代表动态响应好，阶跃响应测试是不可省略的。
<!-- /upkie-qa -->

4. 如果指标退化 20%，你先查模型、数据、控制还是部署？为什么？

<!-- upkie-qa:H04-q4 -->
先查部署，在 FOC 语境下对应的是"硬件连接和传感器"。如果力矩输出退化 20%（比如同样的 Iq 指令，实际加速度比之前小 20%），最可能的根因是硬件层面的变化，而不是控制算法——FOC 的 PI 参数不会因为"软件更新"而自动改变，但硬件连接会随时间退化。排查顺序：第一步查编码器连接（H05 章的 AS5600 编码器如果接触不良或磁钢偏移，电角度估计会出现偏差，FOC 把部分电流注入 d 轴而不是 q 轴，有效力矩下降）；第二步查供电电压（H03 章的供电电压如果下降，PWM 可用电压范围缩小，电流环带宽降低，力矩响应变慢）；第三步查电机温度（永磁体在高温下磁力下降，Kt 降低，同样的 Iq 产生更小的力矩——这是物理退化，不是控制问题）。控制参数（PI 增益）是最后才查的，因为 PI 参数一旦调好不会自己变化，除非有人改了代码。模型和数据在 FOC 问题里不相关——这里没有训练任何模型，Kt 是电机的物理常数。本关正文的"先低能量验证，再逐级闭环"在这里的排查体现是：先断开负载，空载运行 FOC，确认电流环本身正常（Iq 跟踪设定值无误差），再接入负载确认力矩输出——如果空载正常但带载退化，问题在机械负载或供电，不在 FOC 算法。面试时的判断框架：FOC 力矩退化的排查顺序是"传感器 → 供电 → 电机温度 → 控制参数"，从最可能到最不可能。常见误区是"力矩不够就加大 PI 增益"——如果根因是编码器偏移，加大增益只会让电流环振荡，不会增加有效力矩。
<!-- /upkie-qa -->
